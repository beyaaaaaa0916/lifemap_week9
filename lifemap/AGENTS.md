# AGENTS.md — LifeMap 專案指南

## 專案目的

LifeMap 是一個繁體中文的個人願望與人生探索地圖。使用者可以記錄想完成的事、為每件願望補充動機與目標日期、更新完成狀態，並回顧完成心得。這是一個可在 GitHub Pages 執行的純前端靜態網站，不需要伺服器或安裝套件。

本文件是 AI 助理修改本專案時的主要規則。開始工作前先讀完本文件，再查看 `README.md` 與相關程式碼。使用者提出的明確需求優先於一般設計偏好；修改後同步更新文件中受到影響的規則。

## 技術與執行方式

- 使用原生 HTML、CSS、JavaScript；不引入框架、建置工具、外部字型或 CDN，除非使用者明確要求。
- `index.html` 是網站入口，包含頁面結構、樣式與互動程式。此專案刻意維持單頁、零安裝依賴，適合直接以瀏覽器開啟，也可部署至 GitHub Pages。
- 個人願望保存在瀏覽器 `localStorage`，鍵名為 `lifemap-wishes-v1`。資料只存在目前瀏覽器，不會自動同步到不同裝置。匯出功能產生 JSON 備份。
- 瀏覽器可直接開啟 `index.html` 預覽。部署時，GitHub Pages 的來源設為 `GitHub Actions`，使用 `.github/workflows/pages.yml`。

## 網站風格與體驗

- 語言使用繁體中文（台灣用語），語氣溫暖、鼓勵探索，不評斷願望大小或完成速度。
- 延續自然手帳感：奶油白紙張、森林綠、柔和地圖色彩、圓角卡片、清楚留白。CSS 顏色優先使用 `:root` 中的變數。
- 保持響應式排版、鍵盤焦點樣式、表單標籤與按鈕可讀名稱；互動回饋使用既有 toast 元件。
- 新增 UI 時沿用既有按鈕、欄位、卡片與 modal 樣式，不要任意引進第二套視覺語言。
- 使用者提供的文字必須在動態插入 HTML 前經 `escapeHtml()` 處理。日期需透過安全日期處理函式顯示，不要直接將未驗證內容拼進 HTML。

## 頁面結構

1. 頂部品牌與操作：匯出清單、新增願望。
2. 主標題與統計：願望總數、已完成、進行中、完成率。
3. 探索地圖：SVG 地景與依願望狀態呈現的地標。
4. 願望清單：關鍵字搜尋、分類與狀態篩選、願望卡片。
5. 新增／編輯 modal、故事詳細 modal、toast 通知。
6. 頁尾：產品短句與本機資料備份提醒。

除非需求明確涉及新增頁面，新增功能應優先整合到上述區塊，保持單頁操作流暢。

## 檔案與命名

- `index.html`：網站唯一入口與前端實作。
- `AGENTS.md`：AI 專案規則；若改變架構、資料模型或部署方式，必須同步更新。
- `README.md`：專案介紹、功能、執行方式、資料限制及部署步驟。
- `.github/workflows/pages.yml`：GitHub Pages 靜態部署流程。
- `docs/`：新增編輯指南或資料格式說明時放這裡；檔名使用小寫英文與連字號。
- 不新增建置產物、憑證、個人資料、使用者匯出的願望備份或 `node_modules`。

## 願望資料格式

每筆願望使用下列欄位；更新既有資料時需保留未知欄位，避免刪除使用者舊資料：

```js
{
  id: "w_唯一識別碼",
  title: "願望名稱（必填，最多 80 字）",
  category: "旅行 | 學習與技能 | 人生體驗 | 興趣與創作 | 職涯與成就 | 人際與生活",
  description: "願望描述（最多 600 字）",
  reason: "想完成的原因（最多 400 字）",
  targetDate: "YYYY-MM-DD 或空字串",
  status: "todo | doing | done",
  reflection: "完成心得（最多 1000 字）",
  createdAt: "ISO 8601 日期時間",
  completedAt: "ISO 8601 日期時間或空字串",
  mapPosition: { x: 10, y: 77 },
  positionIndex: 0
}
```

狀態對照：`todo` 尚未開始、`doing` 進行中、`done` 已完成。新增分類時要一併更新 `categories`、`categoryIcons`，並確認篩選器、表單與卡片都正常顯示。

## 新增或修改內容的流程

1. 先定位相關 HTML、CSS 與 JavaScript 函式；確認資料欄位是否已存在。
2. 若新增願望分類，同步更新分類清單、圖示與呈現；不得只加下拉選項。
3. 若新增示範願望，須使用正確分類和狀態值，讓使用者能在地圖、卡片、詳細故事及搜尋中看見。
4. 保持新增願望與「補充示範願望」的預設內容一致；若調整預設示範項目，檢查首訪 `starter` 和 `addSamples()` 兩處資料。
5. 保留本機儲存、匯出、搜尋篩選、編輯、狀態切換與手機版操作。
6. 檢視空清單、無搜尋結果、一般清單、完成狀態與 modal 等情境的文字及版面。
7. 如本次任務要求驗證，再使用瀏覽器確認主要操作；不要為小型內容修改增加不必要的套件。
8. 修改後回報檔案與功能變更、已執行的驗證，以及仍需使用者自行完成的發布步驟。

## 禁止事項

- 不得加入需要登入或上傳個人願望的服務，也不得將使用者資料傳到外部伺服器。
- 不要移除 JSON 匯出與「資料儲存在此瀏覽器」提示，除非使用者明確要求替代方案。
- 不要以 `eval` 執行內容；不要把使用者輸入未跳脫地指派給 `innerHTML`。
- 不要提交瀏覽器匯出資料、個人憑證、API 金鑰或私人資訊。
- 不要把網頁當成心理健康、職涯或財務專業建議工具；它是個人目標整理工具。

## 完成標準

- 網站可直接瀏覽，繁體中文內容正確，桌面與手機版排版可用。
- 新增／編輯願望、狀態更新、搜尋篩選、重新整理後資料保留及 JSON 匯出彼此一致。
- 新增功能遵守本文件的資料格式、視覺規則與隱私約定。
- GitHub Pages 部署設定及 `README.md` 中的操作方式與實際專案相符。
